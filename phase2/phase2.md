## 4. Постановка задачи распределения

**Переменные:** x<sub>nt</sub> ∈ {0, 1} – задача t назначена участнику n.

**Производные величины:**
- нагрузка участника: $L_n = \sum_t e_t x_{nt}$;
- удовлетворенность участника: $S_n = \sum_t u_{nt} e_t x_{nt}$ – часы работы, взвешенные тем, насколько задачи нравятся исполнителю.

**Критерии** (оба максимизируются):
- $f_1 = \sum_n S_n$ – суммарная удовлетворенность команды (эффективность: интересную задачу человек делает быстрее и качественнее);
- $f_2 = \min_n S_n$ – удовлетворенность самого "обделенного" участника (справедливость: никто не получает только нелюбимые задачи). Линеаризуется вспомогательной переменной z: $z \le S_n\ \forall n$.

Критерии измеряются в разных масштабах и конфликтуют, поэтому используется свертка с нормировкой на идеальные значения $f_1^*$ и $f_2^*$ (каждый критерий сначала максимизируется отдельно при тех же ограничениях):

$$F = \alpha \frac{f_1}{f_1^*} + (1-\alpha) \frac{f_2}{f_2^*} \to \max, \qquad \alpha = 0{,}5$$

**Ограничения:**

| № | Ограничение | Обоснование |
|---|---|---|
| 1 | $\sum_n x_{nt} = 1\ \forall t$ | У каждой задачи ровно один ответственный исполнитель |
| 2 | $(1-\delta)\bar E \le L_n \le (1+\delta)\bar E,\ \delta = 0{,}15$ | Нагрузка сбалансирована: оценка за фазу общая, вклад должен быть сопоставимым. Точное равенство недостижимо из-за дискретности задач, поэтому допуск ±15% |
| 3 | $x_{n,T1} + x_{n,T2} + x_{n,T3} = 1\ \forall n$ | Каждый описывает одну группу Use Case: все знают продукт и могут осмысленно участвовать в покере планирования |
| 4 | $x_{n,T6} = x_{n,T7}\ \forall n$ | Обе части UCP делает один человек, чтобы оценка факторов была согласованной |
| 5 | $x_{n,T5} + x_{n,T6} \le 1\ \forall n$ | COSMIC и UCP оценивают разные люди: оценки получаются независимыми, нет эффекта "якоря" |

Почему не просто максимум суммы предпочтений: такое решение может отдать одному участнику все любимые задачи, а другому все нелюбимые. Критерий $f_2$ и ограничение на нагрузку защищают от этого. Почему не среднее предпочтение по задачам (как деление суммы на число задач): это делает модель нелинейной, а взвешивание часами учитывает, что большая нелюбимая задача хуже маленькой.
